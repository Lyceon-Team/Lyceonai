# F-69 — the review runner's document is taller than its Focus shell on a phone

Owner ruling (Karl, 2026-10-05): "F-69: fix it in #1073 (shared Focus shell). Proof: 390px
screenshots, light and dark, of the review runner with the LISA input focused and the top bar in
view, plus a regression test where feasible. Also capture one exam module at tablet width to
confirm the shell change doesn't affect it."

Measured 2026-10-05 in Chromium against the student harness (production client build via
`vite preview`, real routers over a local Postgres; paid persona, a fresh review session per
measurement, Reading and Writing misses).

## Cause

The runner's choice buttons (`client/src/components/question-renderer.tsx`) each carry a
screen-reader letter, `<span class="sr-only">A.</span>`. Tailwind's `sr-only` is
`position: absolute`. Nothing between that span and `<body>` was positioned, so its containing
block was the initial containing block: the span sat at its in-flow position (inside the runner's
own scroll area, `CanonicalPracticePage.tsx` `min-h-0 flex-1 overflow-y-auto`) but was clipped by
neither that scroller nor the Focus shell's `<main>`. On a phone the review runner stacks LISA
under the question, so the last choice's letter ("D.") sits below the fold, and it alone
stretched the document past the `100dvh` shell. Any scroll-into-view inside the shell (sending a
LISA message scrolls the thread to the typing dots) then also scrolled the window, taking the
top bar out of view and leaving a blank band under the footer.

The practice runner measured 844 because its choices sit above the fold at 390 (nothing in it
reached below the viewport); it has the same span and the same exposure for a longer question.

## Fix (two `relative`s)

1. `client/src/components/layout/FocusShell.tsx` — `<main>` is `relative` (and carries
   `data-testid="focus-shell-main"`): the shell's scroll area is the containing block of anything
   absolutely positioned inside it, so nothing in any Focus-shell page can make the document
   taller than the `100dvh` shell. This alone brings the document to 844 and keeps the top bar
   in view, as the ruling asked.
2. `client/src/components/question-renderer.tsx` — the choice button is `relative`: the true
   cause. With only (1), the escaped letter moved from the document into `<main>`, so `<main>`
   became scrollable by the overflow (855 px of content in 771) and the blank band reappeared
   under the footer inside the shell once the LISA thread scrolled. With (2) the letter is
   clipped by its own button and the runner's scroller, and `<main>` has nothing to scroll.

`offsetParent` `BODY`. With the shell fix only, the same span's `offsetParent` was
`MAIN#main`.

## Regression checks

- Browser (the real proof; local only, not in CI — the student harness is never part of a test
  run): `expectFitsViewport` in `tests/e2e/student-harness/capture.ts`, set on UI-53's
  `practice-selected`, `review-selected`, `review-lisa-typing`, `review-lisa-focused` and UI-54's
  `timed-module` (desktop, phone, tablet). The capture fails unless the document fits the
  viewport, the window is unscrolled, the top bar is wholly in view and `main#main` has nothing
  to scroll.
- Unit (CI): `client/src/components/layout/FocusShell.test.tsx` ("F-69: the scroll area contains
  its positioned descendants") pins `<main>`'s `relative`; and
  `client/src/components/question-renderer.display-letters.test.tsx` ("the screen-reader letter
  stays inside its choice") pins the button's `relative` and that each button holds its own
  `sr-only` letter.

Plants (each reverted and the file restored after):

| Plant | Browser check | Unit test |
|---|---|---|
| `FocusShell.tsx:133` `relative` removed (renderer fix not yet made) | capture failed: `review-selected mobile light: … scrollHeight 928 vs innerHeight 844` | FocusShell.test.tsx F-69 test failed: `expected [ 'min-h-0', 'flex-1', …(1) ] to include 'relative'` |
| `question-renderer.tsx:201` `relative` removed (shell fix in place) | capture failed: `review-selected mobile light: … main#main scrollHeight 855 vs clientHeight 771` | display-letters F-69 test failed: `expected [ 'transition-none', …(21) ] to include 'relative'` |

With both fixes in place, removing only the shell's `relative` no longer reddens the browser
check: the renderer fix removed the only element that escaped. The shell's `relative` is the
containment for whatever a Focus-shell page adds next; its unit test is what guards it.
